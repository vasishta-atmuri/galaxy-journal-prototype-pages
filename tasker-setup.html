A real phone observation, brought into your journal.

Tasker setup required. This sender uses documented Tasker functions but has not been run on your handset. Journal receives a selected file; it does not silently read other apps or grant Tasker’s Android permissions.
  1. Install/open Tasker on your phone. Create a task named Journal location. Allow Tasker location access when Android asks. Keep device location switched on.
  2. Add a JavaScriptlet action. Copy the location sender script into its Code field. Leave Auto Exit enabled and use an action timeout of at least 60 seconds.
  3. Run the task manually. It requests one GPS fix, checks freshness and writes a new Download/journal-context-….json file. Allow Tasker file access if requested. If GPS or file access fails, it reports that failure and does not fabricate an observation.
  4. The script opens Journal without putting personal data in the URL. Open My day → Phone context → Import Tasker context and select the new file. Review/name the place before asking AI to use it.
  5. Once this manual route works on your phone, you may attach the same task to a Tasker time or mode-related trigger. That automation has not been device-tested here. No always-on monitoring is required for this first demonstration.

The app labels this record Imported file, because it cannot independently authenticate the sender. Health, Messages, Notes and full-calendar access are separate integrations; this task does not acquire them.

For a simpler real-native demonstration, use Phone context → Use current location directly in Journal. Chrome requests its own location permission. Photos use the device file picker.

Verified references: Tasker JavaScript functions, Tasker location and time variables, Samsung Health’s separate Android SDK.
